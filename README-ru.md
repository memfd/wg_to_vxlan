# L2-связность oVirt через публичный IPv4

[English](README.md)

Коллекция `wg_to_vxlan.ovirt_l2` соединяет по одному существующему Linux-мосту на двух хостах oVirt. Виртуальные машины, подключённые к этим мостам, могут обмениваться Ethernet-кадрами. Хостам нужна IP-связность между публичными IPv4-адресами. WireGuard шифрует трафик, а VXLAN переносит Ethernet-кадры, в том числе широковещательные запросы ARP и DHCP.

```text
+-------------------------+                      +-------------------------+
|       Хост oVirt A      |                      |       Хост oVirt B      |
|         [ ВМ A ]        |                      |         [ ВМ B ]        |
|            |            |                      |            |            |
|      [ Linux-мост ]     |                      |      [ Linux-мост ]     |
|            |            |                      |            |            |
|      [ Порт VXLAN ]     |                      |      [ Порт VXLAN ]     |
|            |            | Публичный IPv4 / UDP |            |            |
|      [ WireGuard ]------+<-------------------->+------[ WireGuard ]      |
+-------------------------+                      +-------------------------+
```

Выберите логическую сеть ВМ, которую нужно продлить на второй хост. Создайте её Linux-мост на каждом хосте через Engine или привычным способом, совместимым с VDSM. На новом сервере с единственным публичным интерфейсом сначала подготовьте отдельный мост по [руководству](docs/operations-ru.md). Имена мостов могут отличаться. Выберите активный мост без тегов и с отключённой фильтрацией VLAN. Для пустого моста предварительно задайте постоянный MAC-адрес. Оба конца должны представлять один Ethernet-сегмент с согласованными настройками IP-адресации, DHCP и MTU. Коллекция настраивает туннель и подключает его к мостам. Регистрация хоста, хранилища и адресация гостевых ОС остаются в ведении администратора.

## Требования

- Управляющая машина с ansible-core 2.19 или новее, доступом по SSH и возможностью повышения привилегий на обоих хостах.
- Два хоста Enterprise Linux 9 с systemd, работающими NetworkManager и firewalld, Python-модулем libnmstate, Linux-мостами и поддержкой WireGuard и VXLAN в ядре. В подключённых репозиториях должны быть доступны инструменты WireGuard и необходимые системные пакеты.
- На каждой стороне фиксированный публичный IPv4-адрес на интерфейсе хоста, рабочий маршрут к соседнему узлу и UDP-порт, на который сосед может отправить пакеты. Учтите также межсетевые экраны провайдера.
- Выбранный мост на каждом хосте, свободные имена туннельных интерфейсов, два свободных адреса внутри WireGuard и один VNI для пары.
- Один путь пересылки между мостами. Второй L2-путь может создать петлю для широковещательных кадров и кадров с неизвестным MAC-адресом получателя.

## Установка и подключение

Соберите коллекцию из текущего каталога и установите на управляющей машине.

```bash
mkdir -p dist
ansible-galaxy collection build --output-path dist
ansible-galaxy collection install dist/wg_to_vxlan-ovirt_l2-1.0.0.tar.gz
```

Скопируйте пример inventory и отредактируйте данные обоих узлов в группе `ovirt_fabric`.

```bash
cp examples/inventory.yml inventory.local.yml
```

Замените демонстрационные адреса, укажите имена существующих мостов и сверьте публичный интерфейс с маршрутом ядра до соседа. В примере WireGuard использует UDP 51820, а VXLAN внутри туннеля использует UDP 4789. На обеих сторонах задайте одинаковые порты WireGuard и VXLAN и одинаковый VNI.

Запустите playbooks с управляющей машины, включив оба доступных по SSH хоста в один запуск.

```bash
ansible-playbook -i inventory.local.yml wg_to_vxlan.ovirt_l2.site --syntax-check
ansible-playbook -i inventory.local.yml wg_to_vxlan.ovirt_l2.site
ansible-playbook -i inventory.local.yml wg_to_vxlan.ovirt_l2.verify
```

Проверьте связность между гостями по инструкции ниже. Чтобы ВМ сохранила сетевую связность после миграции, на обоих хостах oVirt должны быть доступны её логическая сеть и профиль vNIC. Для миграции также необходимы совместимые вычислительные ресурсы и хранилища. [Развёртывание и проверка](docs/operations-ru.md)

## Проверка коллекции

На управляющей машине создайте окружение Python, установите зависимости контроллера и запустите локальные проверки сборки.

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-dev.txt
bash tests/check.sh
```

Проверки охватывают логику конфигурации, сборку и установку архива Galaxy и запуск проверок playbook с тестовым inventory. Развёртывание, перезагрузку и передачу гостевого трафика требуется проверить на паре хостов EL9. Перед первым подключением сверьте ключи SSH обоих серверов через доверенный канал.
